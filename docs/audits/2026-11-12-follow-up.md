# Follow-up fixes

This batch addresses ADC ownership and sampling-buffer safety, SD timer rollover and the SHA host fallback. Physical DMA sequencing, HSTX frame timing, glitch circuitry and actual RP2040 support remain outside this batch.

## Evidence → fix → verification

- **O01, P0:** ADC arbitration forcibly reassigned ownership after a spin threshold. Acquisition now returns `bool`, stops after a 1 ms deadline or 10,000 attempts, and preserves the owner's nesting depth on failure. Every production acquisition call checks failure before touching ADC hardware. Scalar legacy reads return zero on contention; sweeps retain previous measurements. Releases by the wrong core return false. Nested acquisition by the owner remains supported.
- **O03, P1:** Sampling and completed-buffer copies previously shared ping-pong storage without mutual exclusion. Both now acquire the ADC ownership guard, so a producer cannot recycle a buffer during another core's copy. This is a bounded serialization repair for the existing synchronous implementation, not an autonomous DMA implementation or lock-free snapshot claim. Initialization/deinitialization still require quiescent callers.
- **O09, P1, partial:** SD ready/token/initialization waits now compare unsigned elapsed time to timeout, avoiding `start + timeout` overflow around the millisecond timer wrap. Sector arithmetic and capacity validation remain open.
- **O12, P2:** Fixed an invalid SHA round constant token. Independent SHA known-answer tests revealed a second defect at message lengths 63 modulo 64: the padding byte filled a block that was not transformed before appending the length. The host fallback now processes that block. Tests use Python `hashlib` as the oracle for fourteen lengths and ten streaming chunk sizes under optimized and optimized ASan/UBSan builds.

The SHA test extracts the exact host-only hash functions from the production translation unit to compile them without CLI/SDK dependencies. It does not test the FatFS command handler or the RP2350 accelerator implementation. No hash functions are replaced with mocks.

The ADC regression holds ownership on simulated core 0 and attempts acquisition, release, reads, sampling and snapshot copying on simulated core 1. It verifies failure leaves the original owner, nesting depth, mux channel and caller output untouched, then verifies normal handoff after release. This reproduces the ownership defect deterministically but is not a hardware inter-core scheduling test.

No new runtime heap allocation or global sampling buffers were introduced. Existing scalar read APIs cannot distinguish contention from a measured zero; a future status-bearing measurement API would make this explicit. The existing physical spinlock is held only while changing ownership metadata, never through ADC conversion or buffer copies.
